# Claude에 그대로 붙여넣을 제작 요청 프롬프트

당신은 영어 교육과정 설계자, 교육용 콘텐츠 QA 담당자, 시니어 프론트엔드 개발자 역할을 협업 수행합니다. 목적은 **기초 영어부터 TOEIC·2026년 개정 TOEFL iBT까지** 장기간 공부하는 한국어 기반 개인 학습 웹사이트를 실제로 만드는 것입니다.

## 반드시 먼저 확인할 파일

1. `01_학습_로드맵.md`: 교육 내용과 학습 정책
2. `02_웹사이트_기능_명세.md`: UI/기능/데이터/게시 정책
3. `04_초기_검증_레슨.json`: 첫날부터 사용할 자체 제작 수업 데이터
4. `05_출처_검증_가이드.md`: 공식 자료 및 환각 방지 정책

**모든 기능과 콘텐츠는 위 네 문서를 단일 기준으로 사용하되, 상충하는 경우 '학습 사실 정확성 > 최신 시험정보 > 저작권·보안 > 진도 보존 > 기능 > 디자인' 순서로 판단하세요.**

## 요구 기능

- React + TypeScript + Vite + Tailwind CSS. 필요 없는 대형 라이브러리 추가 금지.
- 모바일·데스크톱 반응형. 한국어 UI, 영어 예문 표시. 차분하고 가독성 높은 카드형 인터페이스.
- 최초 설치 설정(현재 수준 또는 진단 선택, 학습 목적, 10/25/45분).
- 대시보드: 오늘 수업, 복습 대기, 주간 학습 기록, 단계 및 영역별 진도.
- 일일 레슨: 쉬운 개념 설명, 단어, 영어 예문/한국어 해설, 객관식/배열 문제, 직접 문장 작성, 결과 해설.
- 반복학습: 1/3/7/14/30일의 초기 간격, 오답 재출제, 복습 큐, 개념별 진도.
- 내용 라이브러리: Pre-A1, A1, A2, B1, B2, TOEIC, TOEFL 및 날짜별 검색·필터.
- TOEFL은 **2026-01-21 이후 ETS 최신 형식만** 사용: Reading(Complete the Words, Read in Daily Life, Read an Academic Passage), Listening(Listen and Choose a Response, Listen to a Conversation, Listen to an Announcement, Listen to an Academic Talk), Writing(Build a Sentence, Write an Email, Write for an Academic Discussion), Speaking(Listen and Repeat, Take an Interview). 기본 점수 표시 1~6.
- TOEIC은 L&R Part 1~7, LC 45분/100문항 + RC 75분/100문항, 10~990점. TOEIC Speaking/Writing과 혼동 금지.
- 학습자료는 해당 JSON 파일을 불러오기. UI가 정답을 잘못 표시하지 않도록 검증 스크립트 작성.
- 최초 MVP는 인터넷 없이도 기존 등록 콘텐츠로 학습 가능하도록 정적 JSON + localStorage 또는 IndexedDB로 구현.
- JSON 형태로 진도 내보내기/가져오기 및 버전 검증.
- 음성합성 버튼은 브라우저가 지원하는 경우에만 제공하고 공인 발음 정확성으로 홍보하지 않음.
- 사용자의 로컬 시간대는 Asia/Seoul. 웹 배포 위치가 달라도 같은 날짜 처리.

## 매일 콘텐츠 추가 운영 설계

1. `draft`→정답/데이터 자동 QA→출처 검증→`verified`→`approved`→날짜 공개 흐름을 구현할 것.
2. 기초 원칙: Claude가 만든 미검증 영어 지문·문제·답안은 공개 금지.
3. 공식·학술 출처의 '원문 자체'를 복사·스크래핑하지 말고, 정확한 규칙을 참고하여 **새로운 자체 제작 예문/연습문제** 작성.
4. '매일 최신 자료 수집'과 '매일 검증된 수업 공개'는 서로 다른 처리다. 수집만 되면 공개되는 코드 금지.
5. 초기 단계에서는 사전 검수된 파일을 날짜별로 순차 공개하도록 하고, 후속 확장으로 GitHub Actions/백엔드 작업 예약이 초안을 생성하고 PR로 제안하는 구조를 설계할 것.
6. 실제 배포 자동화를 적용하지 않았을 경우 UI 및 설명에 '매일 자동 업데이트 구현 완료'라고 표시하지 않을 것.
7. 참조 자료가 불확실하거나 공식 시험정보가 충돌하면 자동 게시 중단 및 `needs_review`로 처리.

## 단계별 수행 지침

### 1단계: 설계 출력
- 프로젝트 구조, 페이지 구조, 타입 정의, 콘텐츠 검증 규칙, 저장소 정책을 간결히 제시.
- 이 단계부터 파일을 실제 생성하여 구현 진행.

### 2단계: 코어 구현
- 전체 페이지 및 라우팅, 레슨 로더, 퀴즈 상태, 정답 해설, 오늘/복습 큐, 학습 통계, JSON 백업.
- JSON의 예시 레슨을 가짜로 화면에 하드코딩하는 것은 금지.
- 상태 관리와 컴포넌트를 적절히 분리하고 TypeScript strict 모드 적용.

### 3단계: QA
- 모든 레슨에 대해 정답 인덱스가 보기 범위 안인지, 보기 중복이 없는지, `verified`인지 검사.
- 테스트: 첫 진입, 문제 채점, 새로고침 복원, 현지 자정 전후, 데이터 누락, 모바일 화면, 키보드, 오프라인.
- 검증되지 않은 자료는 **레슨 목록에서 숨김**.
- 학습자에게 테스트 결과를 공인 CEFR/ETS 성적처럼 표기하지 않을 것.

### 4단계: 실행 안내
- 설치, 개발서버 실행, 빌드, 데이터 파일 추가 위치, 학습 진도 백업 및 복원 방법을 한국어로 작성.
- 매일 갱신 기능이 아직 배포되지 않았다면 현재 동작 방식과 필요한 다음 작업을 명확히 기재.

## 콘텐츠 생성 전용 지침

이후 '다음 7일분 콘텐츠를 생성해줘'라는 요청을 받으면 **각 레벨에 대해 새로운 수업 초안**을 JSON 스키마대로 만들되, 출처를 확인하지 않은 사실은 생성 사실로 숨기지 말 것. `review_status: "draft"`로 저장하고 자료의 검증 포인트/근거 링크 목록을 함께 작성할 것. 자동 검증은 오타·정답형식·중복을 찾는 도구일 뿐 정확성에 대한 최종 보증이 아니다.

## 절대 금지

- 시험 문항을 'ETS 공식 기출'이라고 허위 표시.
- 2026 TOEFL을 0~120 점수 또는 과거 4-task speaking 방식으로 기본 소개.
- 확인하지 않은 CEFR 인증/시험 점수 예측.
- 출처 없이 생성한 규칙에 임의 논문/링크 붙이기.
- 교육기관의 저작권 있는 본문·음성·시험문제를 권한 없이 복제.
- API 비밀키를 Vite 프론트엔드 코드에 노출.
- 검증되지 않은 AI 레슨을 운영 데이터에 자동 편입.

**시작:** 첨부된 4개 파일의 내용을 읽고, 바로 개발 가능한 구현 계획을 짧게 제시한 다음 코드를 생성하고 테스트까지 수행하세요. 구현이 어려운 기능은 '미구현'으로 구분하세요.
