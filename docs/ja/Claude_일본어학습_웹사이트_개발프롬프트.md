# Claude에게 전달할 일본어 학습 웹사이트 개발 프롬프트

당신은 일본어 교수설계 전문가, React/TypeScript 시니어 개발자, QA 엔지니어입니다. 아래 첨부한 `일본어_장기학습_설계서.md`와 `일본어_입문_28일_초기데이터.json`을 기반으로, 한국어 사용자가 히라가나부터 JLPT N1 수준까지 장기간 공부할 수 있는 일본어 학습 웹사이트를 **실제 실행 가능한 프로젝트**로 구현하세요.

## 절대 요구사항
1. 검증할 수 없는 일본어 어휘·문법 사실을 만들어 내어 확정 사실처럼 게시하지 마세요. 제작 자료에는 출처와 `content_status`를 유지하세요. JSON의 `linguistic_review_pending`은 **검수 완료가 아닙니다**. 검수자가 `published`로 전환할 때까지 일반 학습 모드에서 사용하면 안 됩니다. 다만 개발·시연 모드에서는 상단에 '교육자료 초안/검수 전' 표시를 두고 이 초기 데이터를 활용할 수 있습니다.
2. JLPT 공식은 2010년 이후 정해진 단어/문법/한자 목록을 공개하지 않습니다. 임의 목록을 '공식 N1 단어' 등으로 표시하지 말고 **사이트 자체 교육 난도**라고 표시하세요.
3. JLPT 실제 문제를 허가 없이 복사하지 마세요. 공식 샘플 자료는 출처 링크로 안내하고 문제는 독창적으로 제작하세요. 원문·음원·삽화 외부 자료를 무단 다운로드해 서버에 재호스팅하지 마세요.
4. 일본어 기본 글꼴·후리가나(HTML ruby/rt)·작은 っ/ゃ·ゅ·ょ·탁음·장음이 제대로 표현되게 해 주세요. 로마자는 입문 초기 2개월에만 기본 노출하며 단계 진전에 맞춰 숨기거나 토글로 전환하세요.
5. '하루 업데이트'는 두 가지로 나누세요. (A) 사용자의 학습 진도/복습 결과에 따라 오늘 공부할 **검증된 데이터**를 자동 할당하는 기능은 MVP에서 구현. (B) 외부 웹에서 자동 수집하고 새 학습 자료를 AI로 생성하여 게시하는 기능은 승인형 파이프라인으로 구조만 준비; 무검수 자동 게시 금지.
6. 15분/30분/60분 세 가지 학습 모드, 월~금 신학습, 토 적용, 일 테스트, 복습 스케줄 기본 D+1, D+3, D+7, D+14, D+30을 지원하세요. 복습 밀림이 심하면 새 학습 항목을 줄이세요.
7. 사용자 로컬 데이터는 IndexedDB로 저장하고 JSON 백업 내보내기/가져오기를 구현하세요. 재접속 시 체크포인트와 복습 기록을 복원해야 합니다.
8. 제공 JSON 데이터를 개발 시작 시 스키마 검증하세요. 임의로 가공하거나 단어 뜻·독음을 변경하지 말고 수정 필요 시 원본과 수정 제안을 분리하세요.

## 기술 선택
- 프런트엔드: React + TypeScript + Vite. 스타일은 Tailwind CSS, 반응형/모바일 우선.
- 로컬 DB: IndexedDB(Dexie 또는 표준 API). 상태관리: Zustand 혹은 단순 React 상태 중 합리적 선택.
- 유효성 검증: Zod. 빌드 체크: TypeScript/ESLint. 테스트: Vitest + React Testing Library.
- 외부 AI API 키가 필요하면 절대로 브라우저 코드에 노출하지 마세요. 운영용 API는 나중에 서버로 분리하세요.
- 사용자 콘텐츠 JSON 파일은 정적 seed로 import하되 출처와 스키마 버전을 보존하세요.

## 필수 화면
1. **대시보드**: 오늘의 목표, 공부 가능 시간, 새 강의, 밀린 복습, 누적 학습일, 약한 분야, 오늘 완료율.
2. **단계별 커리큘럼**: 입문 / N5 / N4 / N3 / N2 / N1. 제공되지 않은 미래 데이터는 '추후 추가 예정'으로 표시하며 가짜 강의를 채우지 마세요.
3. **오늘의 학습**: 문자/단어 카드, 발음 재생(TTS를 쓰면 자동생성 음성 표시), 핵심 설명, 예문, 미니 테스트, 완료 처리.
4. **복습**: 예정 카드, 어렵다/보통/쉽다 평가, 간격 반복 일정, 누적 오답 표시.
5. **오답노트**: 문제, 나의 답, 정답, 해설, 원인 태그, 재도전.
6. **성장 리포트**: 단계별 진도, 문제 유형별 정답률, 복습 부채, 최근 4주 학습시간. 실제 데이터를 기반으로 계산하되 학습하지 않은 수치는 0/데이터 없음으로 표시.
7. **콘텐츠 관리자(개발용)**: 초안/검수 대기/검수 완료/발행 상태, 출처 URL, 권리/검수 정보, 승인/반려. 백엔드가 없을 때 관리자 승인을 서버에 영구 저장한다고 거짓으로 표시하지 말고, JSON Export 또는 로컬 시뮬레이션만 제공.
8. **설정/백업**: 공부 시간, 후리가나, 로마자, TTS, 글자 크기, 접근성, 데이터 내보내기·가져오기.

## 학습 동작
- 사용자 최초 방문: 한국어 온보딩 → 처음부터 시작(기본값)/레벨 진단 선택 → 하루 공부 시간 선택 → 첫 강의.
- 오늘 강의 수량은 레벨, 최근 정답률, 복습 부채에 따라 결정. 이미 완료한 강의를 새로 완료 처리하지 마세요.
- 문제의 정답 위치는 무작위로 섞되 실제 `answer_index`가 가리키는 의미가 보존되어야 합니다. 입력형 정답 검사는 대소문자·앞뒤 공백 허용을 별도 정규화 규칙으로 관리하고 오답은 저장하세요.
- 학습 시간 측정은 실제 시작/완료 이벤트를 이용하며, 단순 화면 체류 시간을 '학습 완료'로 쓰지 마세요.
- 로컬 시간대 기준 하루 경계를 정하되 시계 변경·여행 등의 이상 상황에서도 복습 데이터가 손상되지 않게 합니다.
- 레벨 승급 기준(가이드): 단계별 내부 평가 85% 이상, 영역별 70% 이상 및 필수 학습 완료. 이 수치는 **사이트 자체 기준**이므로 JLPT 공식 점수처럼 표시하지 않습니다.

## 신뢰성·교수설계 검증
- 앱 생성 전 입력 파일 스키마, 중복 ID, prereq 순서, 정답 유일성, 필수 해설 존재 여부를 검사한 보고서를 출력하세요.
- 일본어 내용 검증 3단계: (1) 표기/독음/기본형 일치 확인, (2) 문법 용법·문맥·한국어 해설 대조, (3) 오답 선택지·정답 오류·중복 출제 확인. **독립적인 검토가 불가능하면 미검증을 명시하세요**.
- 최소 테스트 10개: 데이터 로딩, 28일 lesson 정렬, 최초 진입, 하루 15/30/60분 적용, 정답 순서 섞기, 오답 기록, 중복 완료 방지, 복습 예약, 백업 및 복원, 모바일 기본 레이아웃.
- WCAG 대비, 키보드 조작, 스크린리더 라벨, 일본어 텍스트 줄바꿈 확인.

## 단계별 출력 순서
1. 현재 첨부 파일에서 구현 가능한 것과 아직 콘텐츠가 없는 것을 구분한 간단한 구현 계획.
2. 폴더 구조 및 TypeScript 타입/Zod schema.
3. 실제 실행 가능한 MVP 소스코드 전체 생성.
4. 로컬 실행 명령 (`npm install`, `npm run dev`, `npm run test`, `npm run build`).
5. 자동 테스트 결과·검증되지 않은 일본어 내용 및 제약 보고.
6. 콘텐츠 추가·승인·배포를 위한 `CONTENT_GUIDE.md`.

모든 설명·화면·버튼은 기본 한국어로 구성하고 학습 대상 글자/단어/예문은 일본어 원형을 정확하게 사용하세요. 스타일은 차분하고 정보 중심이며 각 학습 카드의 일본어 글자가 충분히 크게 보이도록 디자인하세요.
